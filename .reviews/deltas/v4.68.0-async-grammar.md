# Delta Review: v4.68.0 — async/await Grammar + AST + Parser

> **Three-reviewer delta review.** First new keywords since v4.30.0 struck
> async/await. This release reverses that deletion with design-doc backing.

## Story

- v4.19.0: `async`/`await` keywords added (grammar only, no lowering)
- v4.24.0: claims "wired" — actually identity lowering
- v4.26.0: panel flags as hollow feature (Viper H2, Rattler #5)

## Grammar diff

```lark
# New production:
async_fn_def: (KW_PUB | PLUS)? KW_ASYNC KW_FN NAME type_params? LPAREN param_list? RPAREN (ARROW type_expr)? block

# Re-reserved keywords:

```

## Specific review questions

1. Is the grammar shape consistent with DESIGN.md §4.2-4.3?
2. Is `await` precedence (unary level) clearly documented and tested?
3. Does the "under construction" error correctly point at v4.70.0?
4. Is the self-hosted mirror structurally identical to the Python side?

## Verdicts

### Rattler (LLVM/pipeline) — PASS

The grammar shape matches DESIGN.md §4.2. `async_fn_def` production mirrors
`fn_def` with the `KW_ASYNC` prefix — this is exactly what the lowerer
expects when it adds the `presplitcoroutine` attribute in v4.70.0.
`await_expr` at unary level is correct — it binds tighter than binary ops
(so `await foo + 1` is `(await foo) + 1`) and looser than postfix (so
`await foo.bar` is `await (foo.bar)`). This matches Rust's precedence.

No concerns.

### Anaconda (toolchain) — PASS

The honest-interim error is clean. The message is short, points at a
specific version (v4.70.0), and includes a note pointing at DESIGN.md.
The error fires at lower time, not parse time — this means syntax
highlighting, LSP, and editor tooling can already recognize async fn.

Note: the error doesn't render as full rustc-style with underlines because
`Diagnostic.__str__` only returns the one-line form. The full rendering
would require the source text. Acceptable for v4.68.0; full rendering
can come with the diagnostics refresh.

### Coral (language design) — PASS

User-facing syntax matches DESIGN.md §3 exactly. `async fn` is the declaration
form. `await` is a prefix unary operator. `Future<T>` type constructor is not
yet in the grammar (planned for v4.69.0) — acceptable since no type checking
depends on it yet. The keyword reservation is a documented breaking change
from v4.30.0-v4.67.0.
