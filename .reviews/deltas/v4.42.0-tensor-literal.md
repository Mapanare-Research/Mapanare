# Delta Review — v4.42.0 Tensor Literal

**Feature:** Tensor literal syntax `Tensor<Float>[[1.0, 2.0], [3.0, 4.0]]`
**Reviewers:** Rattler (runtime crossing) + Coral (syntax design)

## Changes

- Grammar: `tensor_literal`, `tensor_body`, `tensor_elem`, `tensor_atom` in mapanare.lark
- AST: `TensorLiteral` dataclass in ast_nodes.py
- Parser: `tensor_literal` transformer with shape inference + jagged detection
- Semantic: `_check_tensor_literal` with element type checking
- MIR: `TensorInit` instruction
- Lowering: `_lower_tensor_literal` in lower.py
- LLVM emitter: `_do_tensor_init` + `_emit_drop_glue_tensors`
- Runtime: 10 `__mn_tensor_*` functions in mapanare_gpu_builtins.c
- Self-hosted: TensorLit + TensorInit variants, stub emitter

## Coral (Syntax Design) — PASS

- Jagged detection is at parse time, not semantic time (rustc-quality)
- No grammar ambiguity with list literals in call-arg positions
- `tensor_atom` restriction is reasonable; `paren_expr` is the escape hatch
- Flattening to row-major is correct by construction
- `Tensor<Type>` prefix provides clean LALR disambiguation from tensor_type
- 13/13 parser tests pass

## Rattler (Runtime Crossing) — PASS WITH NOTES

- CPU fallback correctly sizes buffer (checked multiply, calloc)
- Drop glue frees all three allocations (data + shape + struct)
- ABI signatures match exactly between LLVM emission and C runtime
- No tensor-specific memory safety issues (OOB, UAF, double-free)
- Element stores are bounds-checked in the C runtime

Notes (non-blocking):
- N1: Pre-existing compound-struct-return early exit can leak tensors (row #49)
- N2: Bool tensors use 8 bytes per element (acceptable for v4.42.0)
- N3: Silent no-op on OOB store should become diagnostic for user-facing indexing

## Overall Verdict

Coral: **PASS**
Rattler: **PASS WITH NOTES**
Combined: **PASS** — all notes are non-blocking and pre-existing or future-scoped.
