# Migration Guide: v4.58.0 to v4.59.0 — llvmlite JIT Removal

> **v4.59.0** removes `mapanare/jit.py` and the `llvmlite` Python dependency.
> `mapanare jit` and `mapanare run --release` no longer exist.

---

## What is being removed in v4.59.0

| Component | File | Description |
|-----------|------|-------------|
| `jit.py` | `mapanare/jit.py` | llvmlite-based JIT compiler (~285 lines) |
| `mapanare jit` | `mapanare/cli.py` | JIT-compile and run CLI command |
| `mapanare run --release` | `mapanare/cli.py` | LLVM JIT path for `run` command |
| `llvmlite` dependency | `pyproject.toml` | Python package dependency |

**Not removed:** `mapanare build` still works — it now uses `clang -c` instead
of llvmlite to compile LLVM IR to object code.

---

## Migration paths

### If you use `mapanare jit foo.mn`

**Replacement:** `mapanare run foo.mn` (C backend, default) or `mapanare build foo.mn && ./foo` (LLVM native binary).

### If you use `mapanare run --release foo.mn`

**Replacement:** `mapanare run foo.mn` (C backend is now the only `run` path).
For native-optimized execution: `mapanare build -O2 foo.mn && ./foo`.

### If you use `mapanare build foo.mn`

**No change needed.** `mapanare build` now uses `clang -c` instead of llvmlite
internally. Requires `clang` on PATH (was already required for linking).

### If you import `mapanare.jit` in your own code

Replace with subprocess calls to `clang`:

```python
# Before:
from mapanare.jit import jit_compile_and_run
jit_compile_and_run(llvm_ir)

# After:
import subprocess, tempfile
with tempfile.NamedTemporaryFile(suffix=".ll", mode="w") as f:
    f.write(llvm_ir)
    f.flush()
    subprocess.run(["clang", "-O2", f.name, "-o", "/tmp/a.out"], check=True)
subprocess.run(["/tmp/a.out"], check=True)
```

### If you depend on `llvmlite` via `pip install mapanare[llvm]`

The `[llvm]` optional dependency group has been removed. Remove it from
your requirements.
