# Migration Guide: v4.57.0 to v4.58.0 — Python Emitter Removal

> **v4.57.0** adds deprecation warnings. **v4.58.0** deletes the code.
> This guide helps you migrate before the deletion lands.

---

## What is being removed in v4.58.0

| Component | File | Description |
|-----------|------|-------------|
| `PythonMIREmitter` class | `mapanare/emit_python_mir.py` | The entire Python transpiler backend (~1,220 lines) |
| `mapanare compile` CLI command | `mapanare/cli.py` | Compiles `.mn` to `.py` via `PythonMIREmitter` |
| `mapanare repl` Python execution | `mapanare/cli.py` | REPL evaluates via Python `exec()` on emitted code |
| `_compile_source()` internal function | `mapanare/cli.py` | The Python-backend compile pipeline |
| `_compile_resolved_modules()` | `mapanare/cli.py` | Multi-module Python compilation |
| `_PYTHON_MIR_XFAIL` test set | `tests/conftest.py` | ~55 xfailed tests tracking Python emitter gaps |

**Not removed in v4.58.0:**
- `mapanare/jit.py` (llvmlite JIT) — scheduled for v4.59.0 (A4)
- LLVM backend (`mapanare/emit_llvm_text.py`) — this is the canonical backend
- C backend (`mapanare/emit_c.py`) — default for `mapanare run`
- WASM backend (`mapanare/emit_wasm.py`) — for browser/server targets

---

## Why the Python backend is being removed

The Python transpiler backend has been deprecated since v2.0.0. The LLVM
backend has been the canonical compile path since v4.2.0. The Python backend
was retained for:

1. **Interactive REPL** — `mapanare repl` evaluates code by transpiling to
   Python and calling `exec()`. A native REPL (via JIT or interpreter) is
   the replacement path.
2. **Historical test compatibility** — ~55 tests were xfailed against the
   Python backend. These tests verified features the Python emitter never
   fully implemented (agents, signals, streams, closures).
3. **Bootstrap convenience** — early development used the Python backend
   for rapid iteration. The self-hosted compiler now targets LLVM directly.

None of these use cases justify maintaining 1,220 lines of code that
diverges further from the canonical backend with every release.

## Migration paths

### If you use `mapanare compile foo.mn`

**Before (v4.57.0):**
```bash
mapanare compile foo.mn         # Emits foo.py
mapanare compile foo.mn -o out.py
```

**After (v4.58.0+):**
```bash
mapanare build foo.mn           # Emits native binary via LLVM
mapanare emit-llvm foo.mn       # Emits LLVM IR (text)
mapanare emit-c foo.mn          # Emits C source
mapanare emit-wasm foo.mn       # Emits WebAssembly (WAT)
```

If you specifically need Python source output, there is no replacement.
The Python transpiler was a bootstrapping tool, not a production target.

### If you use `mapanare run foo.mn`

`mapanare run` already defaults to the **C backend** (emit C, compile with
gcc, execute). The `--release` flag uses the **LLVM JIT**. Neither path
touches the Python emitter. No migration needed.

```bash
mapanare run foo.mn             # C backend (default) - no change
mapanare run foo.mn --release   # LLVM JIT - no change
```

### If you use `mapanare repl`

The REPL currently transpiles to Python and executes via `exec()`. In
v4.58.0, the REPL will be removed or replaced with a JIT-based REPL.

**Workaround:** Use `mapanare run` with a source file instead of the
interactive REPL.

### If you use `mapanare jit foo.mn`

`mapanare jit` uses the **LLVM JIT** (llvmlite), not the Python backend.
No migration needed for v4.58.0.

Note: `mapanare jit` itself is scheduled for removal in v4.59.0 (A4:
llvmlite JIT removal). `mapanare run --release` is the replacement.

### If you import `PythonMIREmitter` in your own code

**Before:**
```python
from mapanare.emit_python_mir import PythonMIREmitter
from mapanare.lower import lower as build_mir

mir_module = build_mir(ast, module_name="mymod")
emitter = PythonMIREmitter()
python_code = emitter.emit(mir_module)
```

**After:**
```python
from mapanare.emit_llvm_text import LLVMTextEmitter
from mapanare.lower import lower as build_mir

mir_module = build_mir(ast, module_name="mymod")
emitter = LLVMTextEmitter()
llvm_ir = emitter.emit(mir_module)
```

The LLVM IR output can be compiled to a native binary with `clang` or
executed via the JIT.

### If you have CI that parses Python emitter output

Rewrite your CI to consume LLVM IR instead. The LLVM IR text format is
stable and well-documented. Use `mapanare emit-llvm foo.mn` to generate it.

## Test infrastructure changes

### `_PYTHON_MIR_XFAIL` in `tests/conftest.py`

v4.57.0 retargets the tracking version from v5.0.0 to **v4.58.0**. The
~55 xfailed tests in this set will be deleted along with the emitter in
v4.58.0.

If you have custom tests that depend on `PythonMIREmitter`, migrate them
to use `LLVMTextEmitter` or `CEmitter` before v4.58.0.

### Warning behavior in tests

v4.57.0 adds `DeprecationWarning` at three levels:

1. **Import time** — `import mapanare.emit_python_mir` fires a warning
2. **Instantiation** — `PythonMIREmitter()` fires a warning
3. **Emission** — `emitter.emit(module)` fires a warning

By default, Python suppresses `DeprecationWarning` unless the code is in
`__main__`. In pytest, warnings are captured and can be asserted:

```python
import pytest

def test_my_migration():
    with pytest.warns(DeprecationWarning, match="v4.58.0"):
        from mapanare.emit_python_mir import PythonMIREmitter
```

If your CI uses `-W error::DeprecationWarning`, these warnings will become
errors in v4.57.0. This is intentional — it surfaces the deprecation in CI
pipelines that treat warnings as errors.

## FAQ

### Q: What if I rely on Python-specific features the LLVM backend doesn't support?

Report it before v4.58.0 ships. Open an issue describing your use case.
The LLVM backend has full parity with the Python backend for all shipping
language features (functions, structs, enums, pattern matching, closures,
agents, signals, streams, Result/Option, generics, traits, imports).

### Q: Can I keep using the Python backend after v4.58.0?

No. The file will be deleted. If you need it, pin your dependency to
v4.57.0, but you will not receive any further updates or bug fixes for the
Python backend.

### Q: Will the REPL work after v4.58.0?

The current REPL (`mapanare repl`) depends on the Python backend and will
be removed in v4.58.0. A replacement REPL (JIT-based or interpreter-based)
is planned but not yet scheduled.

### Q: I'm getting `DeprecationWarning` errors in CI. How do I suppress them?

If your CI uses `-W error`, you can selectively ignore this warning:

```bash
python -W error -W "default::DeprecationWarning:mapanare.emit_python_mir" -m pytest
```

Or in `pytest.ini`:

```ini
[pytest]
filterwarnings =
    error
    default::DeprecationWarning:mapanare.emit_python_mir
```

But the better fix is to migrate away from the Python backend entirely.

### Q: Does this affect the self-hosted compiler?

No. The self-hosted compiler (`mapanare/self/*.mn`) targets LLVM IR via
`emit_llvm.mn`. It has never used the Python backend.
