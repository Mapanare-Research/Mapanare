## Scope

Every golden test in `tests/golden/` currently validates the *shape* of emitted LLVM IR via string matching. That catches emitter regressions but cannot catch miscompilation, ABI bugs, or optimizer-induced failures. Anaconda has flagged this every panel since Arc 3: "pipeline integration test still open."

v4.77.0 builds a pytest-based integration framework that takes each `.mn` golden test through the full native pipeline: `mnc-stage1` (or the Python bootstrap) emits `.ll`, then `llvm-as` validates it, `opt -O2` optimizes it, `llc -filetype=obj` generates an object file, `clang` links it against the C runtime, and the resulting binary runs with its stdout captured and compared against an expected-output file. The framework tracks pass/fail per test and generates a results report.

## Phase 1 — Framework design and scaffolding

- [ ] Create `tests/integration/conftest.py` with pytest fixtures:
  - `compile_mn(source_path)` — calls `python -m mapanare emit-llvm <source> -o <tmpdir>/<name>.ll`
  - `assemble_ll(ll_path)` — calls `llvm-as <ll_path> -o <bc_path>`
  - `optimize_bc(bc_path)` — calls `opt -O2 <bc_path> -o <opt_path>`
  - `codegen_obj(bc_path)` — calls `llc -filetype=obj <bc_path> -o <obj_path>`
  - `link_binary(obj_path)` — calls `clang <obj_path> -L<runtime_dir> -lmapanare_rt -lm -lpthread -o <binary_path>`
  - `run_binary(binary_path, timeout=10)` — executes and captures stdout/stderr/exit code
  - `full_pipeline(source_path)` — chains all of the above, returns `(exit_code, stdout, stderr)`
- [ ] Create `tests/integration/expected/` directory with expected stdout files: `<test_name>.expected`
- [ ] Create `tests/integration/test_golden_pipeline.py` — parametrized test that discovers all `tests/golden/*.mn` files and runs each through `full_pipeline`

## What this release does NOT do

- **Fix tests that fail through the pipeline** — that is optimizer or emitter work for future arcs. v4.77.0 only builds the harness and documents which tests pass and which do not.
- **Change IR emission** — no modifications to `emit_llvm_text.py` or self-hosted emitters.
- **Run integration tests on the self-hosted compiler** — v4.77.0 uses the Python bootstrap. Self-hosted integration is a future arc.
- **Windows CI** — integration tests target Linux (Ubuntu) only. WSL is the local development path.

## Risk register

| Risk | L | I | Mitigation |
|---|---|---|---|
| LLVM toolchain version mismatch between local and CI | medium | medium | Pin LLVM version in CI (e.g., `llvm-17`) and document in `RESULTS.md` |
| Some golden tests produce no stdout (e.g., type-checking-only tests) | medium | low | Expected file can be empty; the pipeline pass/fail still matters |
| C runtime link fails because of missing symbols | medium | high | Ensure `make build-rt` runs before integration tests in CI; document required build order |
| `opt -O2` exposes IR bugs that pass `llvm-as` | high | medium | This is a feature, not a bug — the harness reveals these. Mark as xfail with tracking |
| Integration tests are slow (57 tests x full pipeline) | medium | low | Parallelize with `pytest-xdist -n auto`; target < 5 minutes total |
