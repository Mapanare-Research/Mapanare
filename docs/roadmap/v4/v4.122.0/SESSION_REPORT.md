## Self-graded aggregate

**8.6 / 10**

- **The fix is minimal and at the right layer.** Root cause isolated
  in two diagnostic sessions — MIR inspection showed `%arr.ty.args
  = [<unknown>]` at the IndexGet emission site, LLVM IR diff against
  bootstrap showed the missing `load i64` instruction. Neither the
  emitter nor the semantic checker needed to change; the lowerer's
  existing empty-list patch block at lines 1253–1261 already handled
  the `ListInit.elem_type` but stopped short of lifting the Value
  that downstream uses inherit. One extra line at 1268 closes the
  gap. No helper functions, no new abstractions, no refactor. +strong
- **Regression test surface is comprehensive.** Five IR-level tests
  pin the behaviour at four different assertion angles: the emitter
  output for `List<Int>` must have `load i64, ptr`; the let-binding
  case must not use `ptrtoint`; arithmetic must operate on two
  independent i64 loads; `List<Float>` must emit `load double, ptr`;
  `List<MyStruct>` must still load the struct aggregate as an
  inline `{i64, i64}`. Plus the new golden test
  (`65_list_int_indexing.mn`) exercises all five usage patterns
  through the full pipeline. A future regression in any of these
  shapes fails CI at PR time. +strong
- **Self-hosted compiler was correctly diagnosed as not needing a
  mirror fix.** Two design differences in `self/lower.mn` and
  `self/emit_llvm.mn` make the bug structurally unreachable:
  `lower_let` unconditionally rewrites `val_ty = declared` when an
  annotation is present (stronger than Python's "only if
  `val.ty.kind == UNKNOWN`" check); `emit_index_get` always emits
  a load and defaults to `load i64` when dest type is unknown, which
  masks the UNKNOWN-propagation bug even if it happened. Verified
  empirically: the v4.121.0 `mnc-stage1` binary (built before my
  fix) already produces the correct `42 / 42 / 99 / 100 / 141`
  output for the new golden test. Phase 4 of PLAN correctly marked
  as "documented as not-applicable." +solid
- **Benchmark/ref.ll surface area.** `mapanare/self/main.ll`
  regenerated as a side effect of `scripts/build_stage1.py` and
  is now part of the commit (1,714 insertions + 1,713 deletions,
  ≈1 net line change; the diff is version-string renames and
  value-name counter renumbering). I did not hand-review every
  changed line; spot-checked the top and bottom and verified the
  golden `stage1` pass count is unchanged (27/65, up from 26/64
  only by the newly-added golden). This is the lightest honest
  verification of autogenerated artefacts — if a behavioural
  regression hid in the reshuffle, the golden-through-stage1 check
  would have caught it. +soft
- **Black wanted to reformat 11 lines in `mapanare/lower.py`

  all pre-existing An.2 carry-forward items.** I reverted black's

- **One new test assertion needed refinement.**

## What shipped

### Compiler changes (1 file, 6 lines)

- **`mapanare/lower.py::MIRLowerer._lower_let`** — after the existing
  `ListInit.elem_type` patch block for empty list literals with a
  type annotation, rebind `val = Value(name=val.name, ty=declared)`
  so the named alias carries the full list element type (including
  `type_info.args`). This is the only line of behavioural change;
  the surrounding four lines are a comment block explaining why
  (referencing the v4.122.0 Qs.1 docket).

### Test additions (2 files)

- **`tests/golden/65_list_int_indexing.mn`** (31 source lines):
  empty-literal-with-annotation declaration, three pushes, five
  usage patterns of indexing (direct `str()` arg, let binding,
  second element, after-mutation, arithmetic), five `print(...)`
  statements yielding `42 / 42 / 99 / 100 / 141`.
- **`tests/golden/65_list_int_indexing.ref.ll`** (270 lines):
  reference IR emitted by the Python bootstrap post-fix. Contains
  21 `alloca i64` (integer-typed slots for IndexGet results) and
  23 `load i64, ptr` loads (one per primitive list element access
  plus intermediate reloads). Zero `alloca ptr` for list elements,
  zero `<?>` string constants.
- **`tests/integration/expected/65_list_int_indexing.expected`**:
  expected stdout (`42\n42\n99\n100\n141\n`).
- **`tests/llvm/test_emitter_hardening.py::TestListIntIndexingQs1`**
  (119 lines, 5 tests): IR-level regression guards. Each test
  compiles a specific shape (empty-literal/annotation, let binding,
  arithmetic, `List<Float>`, `List<Pt>`) and asserts the IR contains
  the correct `load <ty>, ptr` instruction and does not contain
  `<?>` / `ptrtoint`.
