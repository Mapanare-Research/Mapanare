# Ship v4.0.0 — Production Release: Build Real Programs

Fifteen months ago, the first Mapanare commit stubbed out a Lark grammar and a Python emitter. Today, the self-hosted compiler — 15,000+ lines of Mapanare compiling itself through LLVM to a 2.94 MB binary in 0.74 seconds — has been verified to a fixed point (stage4 == stage3), reviewed by seven independent reviewers at 9.79/10 with unanimous PASS and zero CRITICAL issues, and tested across 4,845+ cases. This PR ships everything from v3.0.2 (fixed-point self-compilation) through v4.0.0 (production release) plus the first v4.1.0 ecosystem infrastructure work: 204 commits, 363 files, the entire journey from "the snake bites its own tail" to "you can build real programs."

The headline features are GPU compute, the Python transpiler, and the ecosystem infrastructure. GPU compute delivers 8 built-in functions (`gpu_available`, `gpu_tensor_add/sub/mul/div/matmul`) that dispatch to CUDA via dlopen — no SDK installation, no compile-time dependency, graceful CPU fallback. Tensor operations produce correct results on an NVIDIA RTX 4090 with 24 GB VRAM. The Python transpiler takes any type-annotated `.py` file, converts it to Mapanare, and compiles it to a native binary that runs 29-68x faster than CPython with zero manual edits. Three bugs were found and fixed while building the transpile demo: the MIR optimizer's constant propagation was silently corrupting loop variables through back-edges, the transpiler was inferring function names as types instead of return types, and `cmd_build` was using the output path for both the intermediate `.o` and the final binary.

The C runtime is now 13,355 lines across five files covering arena allocation, lock-free ring buffers, thread pool with work stealing, TCP/TLS (OpenSSL via dlopen), SHA-256/HMAC/base64/hex crypto, PCRE2 regex, HTTP/1.1 client with 64 MB response cap, agent lifecycle management, string interning with configurable cap, memory profiling, and GPU dispatch with embedded PTX kernels. All files compile with `-Werror` under both AddressSanitizer and ThreadSanitizer. All three dlopen loaders use atomic compare-and-swap for thread-safe initialization. The `intern_ensure_table()` race that persisted through five review cycles is fixed. The `__mn_str_concat` double-free that would have hit any program concatenating with an empty string is fixed.

The ecosystem infrastructure — started in v4.1.0 Phase 1 but included in this PR because it was built on the same branch — adds a PostgreSQL connection pool with retry logic (fixing the package-disappearance bug on Render), GitHub OAuth web login with signed session cookies, an account dashboard, a download page with platform auto-detection, and `mapanare-up`, a pyenv-style version manager that resolves `.mapanare-version` files per project.

**MIR optimizer fix (`mapanare/mir_opt.py`)**
- `constant_propagation()` was propagating stale constants through loop back-edges
- Root cause: Copy(dest=%x, src=%y) where %y had a Const definition was replaced with Const(dest=%x, value=init_value), even when %y was reassigned in a prior loop iteration
- Fix: count definitions per variable name; exclude multiply-defined variables from propagation
- Test case: variable-to-variable assignment inside if block inside while loop now produces correct code

**Python transpiler fix (`mapanare/from_python.py`)**
- `_infer_type_from_value()` for Call nodes was returning the function name as the type instead of looking up the function's return type annotation
- Fix: track return types in `_func_return_types` dict during function translation, look up at call sites
- Enables: `result = count_primes(500000)` correctly infers `Int` instead of `count_primes`

**LLVM text emitter GPU dispatch (`mapanare/emit_llvm_text.py`)**
